# GuidHubFront — Project Context

> Компактный контекст для нейросетей и нового чата. Живой статус задач — в `docs/todo.md`.

## Что это
Фронтенд (SPA) для Guidhub — платформы гидов и клиентов. Бэкенд — отдельный репозиторий (модульный монолит .NET 10, ASP.NET Core, PostgreSQL), API под `/api/v1`.

## Ключевая продуктовая модель
- **Гид приводит трафик на себя, а не в общий каталог.** Ссылка гида ведёт на его страницу/мероприятие. Пользователь видит только вещи этого гида.
- **Главная страница — приветственная**, не каталог. Общая версия сайта доступна только по клику на логотип.
- **Сервис для гида — инструмент управления мероприятиями.** Не отпугиваем гида показом чужих мероприятий.
- Вход — только через Telegram Login Widget. JWT в HttpOnly cookie (30 дней, без refresh).
- MVP на русском рынке.

## Стек
- **React + TypeScript + Vite** (SPA, без SSR).
- **React Router** — роутинг.
- **TanStack Query** — запросы к API, кэш.
- **Tailwind CSS + shadcn/ui** — стили и компоненты.
- **react-hook-form + zod** — формы и валидация.
- Пакетный менеджер: **npm** (если не решено иначе).

## Связь с бэкендом
- Базовый URL API (dev): `https://localhost:7028/api/v1`.
- Аутентификация: cookie (`HttpOnly`), поэтому все запросы — с `credentials: 'include'`.
- CORS на бэке должен разрешать origin фронта с `AllowCredentials` (шаг «5.5. CORS для dev-фронта» в бэкенд-todo).
- «Кто я»: `GET /users/me` — возвращает текущего пользователя и его роли (в т.ч. Guide).
- Полный список эндпоинтов — в `docs/API.md` (краткая шпаргалка) и в OpenAPI бэкенда.

## Правила работы
- **Один шаг = один коммит.** После шага `npm run build` зелёный (когда появится сборка).
- **Не перескакивать.** Не делать два шага за раз.
- **Если контекст потерян** — начинать с первого незакрытого шага в `docs/todo.md`.
- Бизнес-логика — в `features/`, страницы в `pages/` тонкие.
- Запросы к API — только через `lib/apiClient` (обёртка над fetch с `credentials: 'include'`).
